# TASK_contract_templates_v2

Нужно создать Windows-программу для генерации договоров TRUST COMMUNAL.

## Цель
Сделать программу, в которой можно:
- хранить мои реквизиты арендодателя один раз;
- создавать и редактировать разные шаблоны договоров внутри программы;
- хранить шаблоны отдельно от кода;
- выбирать шаблон договора из списка;
- заполнять данные договора через интерфейс;
- автоматически подставлять сумму прописью;
- сохранять готовый договор в .docx;
- в будущем иметь возможность легко добавлять новые виды договоров.

## Основные требования

1. Программа должна работать на Windows 10/11.
2. Итоговая версия должна собираться в portable .exe.
3. Программа должна работать без установленного Python.
4. Перенос на другой компьютер должен выполняться простым копированием всей папки программы.
5. Не использовать абсолютные пути.
6. Все данные хранить рядом с программой.

## Структура данных
Нужно предусмотреть папки:
- templates/
- data/
- generated/
- settings/

## Функции программы

### 1. Мои реквизиты
Отдельный раздел, где мои реквизиты арендодателя заполняются один раз и сохраняются.
При следующих запусках они должны автоматически подставляться.

### 2. Шаблоны договоров
Отдельный раздел "Шаблоны договоров", где можно:
- создать новый шаблон;
- редактировать существующий шаблон;
- удалить шаблон;
- сохранить шаблон.

Шаблоны должны храниться отдельно от Python-кода.

### 3. Использование шаблонов
При создании договора пользователь выбирает шаблон из списка.
После выбора шаблона программа подставляет данные в поля.

### 4. Переменные шаблона
Поддержать переменные:
- {contract_number}
- {contract_date}
- {tenant_name}
- {tenant_director}
- {tenant_basis}
- {tenant_address}
- {object_address}
- {area_sq_m}
- {rent_amount}
- {rent_amount_words}
- {term_text}
- {landlord_name}
- {landlord_director}
- {landlord_basis}
- {landlord_address}
- {landlord_details}

### 5. Генерация договора
Программа должна формировать готовый .docx файл по выбранному шаблону.

### 6. Удобство
Интерфейс должен быть простым:
- большие понятные кнопки;
- минимум лишних действий;
- логичное разделение по вкладкам.

## Требования к архитектуре
1. Не зашивать текст всех договоров прямо в Python-код.
2. Логику интерфейса, работу с шаблонами и генерацию документа разделить по модулям.
3. Сделать архитектуру расширяемой для новых типов договоров.
4. Не ломать возможность дальнейшей доработки.
